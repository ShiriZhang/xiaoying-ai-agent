## 资料与规则

- 一个易读 JSON 资料集；每个文档版本有唯一文档 ID、标题、主题、版本日期、生效日期及手工编号短段落。
- 所有资料统一适用，不按员工类别、差旅类型或套餐划分规则。
- 版本日期不等于生效日期，日期较新不自动优先。不额外设置“正式制度优先于 FAQ”等统一权威层级。
- 仅依据资料明确写出的适用范围、替代关系和生效条件消解冲突。相关依据写入可引用正文，元信息与正文一致。
- 当前规则以服务运行当天判断；测试冻结日期。正常运行结果可能因日期变化而改变，记录实际日期与时区，不采用固定演示基准日。
- 修改资料后重新加载并重建两路索引，不做热更新。通过替换原文检查答案、引用和动作是否随之改变。

## 回答与证据边界

- 输入为问题和可选对话历史；对外通过服务端会话管理续接历史，内部执行层接收问题和取出的上下文。
- 企业事实只依据所提供资料。补充检索后仍无依据时说明未覆盖，不能将“未查到”说成“公司没有”。
- 天气等完全无关问题说明服务范围；不扩展为通用知识问答。
- 对话历史、用户陈述、助手旧答案及对话锚点用于理解问题，不自动构成企业规则证据；制度与产品结论每轮重新检索、读取。
- 部分问题有依据时分项交付，未解决部分单独说明冲突或缺口。
- 冲突双方分别引用。缺少消解依据时由模型补充查证，找到候选后读取原文；仍无依据则保留冲突，请求现行制度或替代说明，不让员工凭偏好选规则。
- 若已读原文已明确给出有效替代依据，可直接解释，不为凑步骤重复检索。
- 每条引用包含文档 ID、版本日期、片段标识和连续逐字原文，回答以 [C1] 等标记逐项关联。
- 模型选择本轮已读取的片段，程序校验读取记录后回填原文与出处；检索摘要不能代替最终原文引用。出处存在性校验不等于语义支持性验证。
- 完整列出资料缺口，每轮最多一个关键追问；无关问题不追问。执行错误单独说明，不伪装成资料不存在。

## 任务状态

| 状态 | 含义 |
| --- | --- |
| 已回答 | 问题有充分依据并完成回答 |
| 待澄清 | 冲突无法消除，或问题含义不明确，需要补充信息 |
| 依据不足 | 属于公司资料范围，但现有资料不足以支持答案 |
| 超出范围 | 与公司资料服务无关 |
| 未完成 | 必要执行因故障、模型不可用、超时或上限中断 |

混合问题整体优先级：未完成 → 待澄清 → 依据不足 → 超出范围 → 已回答。已验证部分、缺口和执行问题仍分项说明；该优先级不替代模型查证和决策。

## Agent 与检索

- Python 原生轻量循环、单 Agent；FastAPI 提供 RESTful API。
- 生成模型为 DeepSeek 官方 deepseek-flash，显式关闭思考；本地中文 embedding 为 BAAI/bge-small-zh-v1.5，先用 CPU。一个生成模型加一个向量模型，不增加必交 Reranker。
- 模型选择动作 → 程序校验并执行 → 将真实观察交回模型 → 模型再次选择或结束。固定分支、自动重试或预设日志不能代替该循环。
- 两种业务工具：检索资料、读取片段；另有结束动作提交回答、引用、缺口、状态、可选追问及锚点快照。每次模型响应只选择一个动作，一次读取最多 3 个片段。
- Query Rewrite 由 Agent 组织及调整查询，根据观察决定改写、扩展、拆分或停止，不为每问固定增加前置改写调用。
- BM25 与向量检索各取前 12 个片段，RRF 融合去重后默认返回 6 个，允许扩大到 12 个；向量在内存中比较。
- 检索返回标识、出处、短摘要和排名，完整原文需读取。相关性不是答案可信度。这些候选参数是待实测调整的初值。
- Reranker 与检索对照实验为可选加分项；优先全部必需验收与交付。

## 会话、短期记忆与运行限制

- SQLite 保存完整问答，重启可续问；不同会话不得混用历史。
- 接口为 POST /sessions、POST /sessions/{id}/messages、GET /sessions/{id}、GET /health；健康检查不触发付费调用。
- 格式错误与不存在会话通过 HTTP 错误表达，进入执行后的任务结果通过任务状态表达。本次为本机演示。
- 短期记忆采用结构化锚点加近期原始问答。锚点只有当前对象、关注事项、待澄清事项，各附来源消息标识，无待澄清项时为空；纠正或换题时更新或清除旧值，不存企业答案、原文引用或员工画像。
- 同一个结束动作生成业务结果及完整锚点快照，程序校验并保存；不新增记忆请求或工具。额外字段仍消耗 token 与时间。
- 业务与锚点分别校验。仅锚点非法时保留合法业务结果，拒绝新锚点、停用旧锚点并告警；下一轮先用近期原始历史，等待合法快照重建。
- 模型失联、超时、达到上限或最终格式修正失败而没有合法结束动作时，停用旧锚点并记录原因；下一轮先用近期原始历史重建，不宣称获得新快照。SQLite 写入失败不伪称保存成功。
- 近期原始历史初始预算为 8000 个估算 token，从新往旧选完整问答轮次，记录实际选入历史，通过真实 usage 校准。锚点、系统指令、当前问题和本轮工具观察另留空间。
- 不设置单问题独立字符上限，不截断当前问题；必要内容仍无法容纳时明确返回未完成。
- 单任务最多 8 次模型决策，包含结束与格式修正；最多 6 次业务工具调用，失败和恢复也计数。预算耗尽且未结束时直接返回未完成与记录，不追加模型收尾。
- 每次任务最多一次由模型决定的工具故障恢复；整体输出不可解析、动作参数或业务结果/引用标识不合法时，最多一次格式修正，仍失败则未完成。两种恢复分别计数，均受总体上限约束。
- 单次模型请求超时 60 秒、任务总超时 300 秒，均可配置。关闭客户端隐式重试。

## 模型不可用与 Mock

- 真实模式鉴权失败、服务错误或超时时明确未完成，不自动切换 Mock。
- Mock 显式启用，模拟生成动作与向量编码，复用执行器、BM25、融合及读取，不联网或下载权重。
- 输出和 Trace 标明 Mock，既不证明真实决策，也不证明真实语义检索效果。真实 embedding 失败是检索工具错误，不静默退化为仅 BM25。
