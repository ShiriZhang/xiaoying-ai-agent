# 方案设计

采用Python原生单Agent循环，以FastAPI提供HTTP接口，SQLite保存会话，本地BM25与中文向量检索提供资料。执行器负责可靠执行和校验，模型负责组织查询、选择动作及解释证据。

## 调用流程

1. API校验问题并读取服务端会话，取得本任务一致的资料与索引快照。
2. 组装系统约束、当前问题、任务日期、合法锚点与近期完整问答。
3. 调用DeepSeek，由模型选择search、read或finish。
4. 程序校验动作并执行工具，记录参数和真实观察，再交回模型。
5. 模型据观察补查、读取、追问或结束；执行器校验结果和引用，分别校验记忆。
6. 在短事务中保存问答、完整结果及Trace，返回业务状态与持久化结果。

正常问题通常为search → read → finish；期限冲突则读取双方后补查并读取新相关候选，再决定是否澄清。查询改写发生在模型选择search时，没有固定额外的前置改写请求。工具故障作为真实观察交回模型，恢复或停止由模型决定。

## 模型与依赖取舍

生成模型为官方deepseek-flash，显式关闭思考、temperature=0，关闭隐式重试；记录请求与响应实际模型标识。temperature=0不保证确定性。适配使用标准库HTTP，不引入模型SDK或Agent框架，便于直接解释每次调用与停止行为。

向量模型为BAAI/bge-small-zh-v1.5，固定revision `7999e1d3359715c523056ef9478215996d62a620`，本地CPU加载并核对六个权重文件的SHA-256。运行阶段不下载权重。

FastAPI 0.115.14负责接口，Pydantic 2.11.7负责请求结构，Uvicorn 0.34.3负责服务，python-dotenv 1.1.1读取显式配置；真实编码使用torch 2.9.0+cpu与transformers 4.57.1。完整依赖及来源以[pyproject.toml](../pyproject.toml)和[uv.lock](../uv.lock)为准。

## 检索与资料一致性

BM25采用NFKC/casefold、汉字单字/双字与拉丁连续词切分，k1=1.5、b=0.75；向量使用CLS表示和单位归一化，中文查询添加检索前缀。编码最长512 token，过长明确拒绝，不静默截断。

两路各取前12个候选，通过RRF（k=60）融合去重，默认返回6个，可扩大至12个，同分按片段ID排序。检索返回摘要、排名和出处，不把相关性分数解释为规则可信度。小规模资料使用内存精确向量比较，无需单独部署向量数据库。

`RetrievalStore.acquire()`取得不可变索引。任务中的检索、读取、引用共用同一快照；`reload()`完整验证并重建两路索引成功后才发布新版本，失败保留旧版本，既有任务继续使用旧快照。

## 引用、冲突与结果校验

模型结束时提交引用标记、片段ID和资料指纹。执行器要求其属于本任务成功读取集合，从快照回填文档ID、标题、日期及完整逐字原文；拒绝未读引用、跨快照引用、非法标记及模型伪造的原文字段。

此检查保证来源存在，不能自动证明归纳得到原文支持。语义可靠性还通过真实运行和逐条阅读答案、引用、限定条件来验证。冲突不按日期自动裁决；只有正文提供有效替代或适用依据时才可消解。

finish包含整体状态、分项状态、回答、引用、缺口、最多一个关键追问及完整锚点。程序检查状态优先级和引用关联；执行错误单列，不充作资料缺口。中断时保留已取得证据，不额外调用模型编造收尾。

## 会话与短期记忆

SQLite的sessions、runs、messages保存会话锚点、完整结果/Trace和业务消息。同会话以进程内锁顺序执行，模型等待期间不持有数据库写事务；没有多进程协调承诺。

历史窗口默认8000个估算token，从新往旧选完整问答轮次，不拆轮次；完整历史仍在SQLite。当前问题、系统约束、锚点与本轮工具观察另行保留，不截断当前问题。每次模型请求记录估算量与可获得的真实usage供对照，估算不是精确tokenizer。

锚点仅含subject、focus、pending_clarification，各项附本会话来源消息ID。与业务结果同一次finish生成，不新增记忆模型请求。保存“报销提交期限”等关注事项，不保存“15天与30天冲突”等企业结论；换题、纠正和问题解决时替换或清空。

新旧锚点均检查。仅锚点非法时保留合法答案、拒绝新值并停用旧值；无合法结束时同样停用旧锚点。下一轮暂用近期原始历史重建。内容检查是有限规则，仍可能漏判或误判，不能保证任意自然语言的语义正确性。

## 执行边界与故障

- 最多8次模型、6次工具调用；第6工具完成后尚未结束则立即返回incomplete，不追加收尾。
- 最多一次模型决定的工具恢复、一次独立格式修正，均受总预算约束。
- 在单动作、立即停止和一次修正规则下，实际最多7次模型请求；第8次不可达，见[计数说明](../examples/batch-3/budget-decision.md)。
- 默认单模型60秒、总任务300秒，可配置；任务使用一致的日期与时区，计时采用单调时钟。
- 模型/编码器失败不自动切换Mock或仅词项检索；存储失败明确报告未保存。
- 超时可停止对外等待，不能强杀底层线程或撤销服务商计费；迟到结果不发布为任务成功。

## 接口与离线模式

提供POST /sessions、POST /sessions/{id}/messages、GET /sessions/{id}和GET /health。健康检查不调用生成模型。非法请求422，未知会话404，存储失败503；已经进入执行的模型/工具失败以200返回业务incomplete及原因。

Mock显式启用，生成动作与向量为受控模拟，复用执行器、BM25、融合和读取。默认演示支持导出格式、分辨率与报销材料，不支持的问题明确未完成，不证明真实模型语义能力。运行命令和完整配置见[README](../README.md)。
