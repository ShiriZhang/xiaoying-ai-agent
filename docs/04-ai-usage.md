- 读取用户提供的笔试原文、当前目录、OpenSpec 状态与适用技能，按决策依赖分轮提出问题、推荐和取舍。

- 通过只读辅助子任务核查环境、官方资料和设计一致性。这属于开发协作，不代表交付项目采用多 Agent 运行架构。
- 起草并维护需求、方案、评估计划和业务术语表；整理已确认结论，清除已被后续决定覆盖的旧未决项。

## 用户已经作出的设计贡献

以下是本对话中实际发生的选择，不是对独立编码能力或已完成验证的推断。

- 明确普通员工需查询制度与产品等多类资料，随后将演示限定为三个主题、12 份短资料。
- 选择单 Agent、DeepSeek、本地 embedding、HTTP RESTful API，并将混合检索列为必交，而非沿用 AI 最初推荐的仅词项检索范围。
- 选择服务运行当天判断当前规则，而非固定演示日期；坚持不设单问题字符上限。
- 从调用方携带历史转向服务端最小会话与 SQLite，讨论实际产品接口的使用方式。
- 主动提出锚点与摘要等记忆策略，经过比较选择结构化锚点加近期原始历史、估算 token 预算与结束动作内生成快照。
- 将任务总超时从建议的 180 秒调整为 300 秒，确认故障恢复、格式修正和记忆失败隔离边界。
