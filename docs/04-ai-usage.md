# AI辅助与个人贡献

本项目使用Codex辅助需求梳理、实现、测试和文档整理。AI生成内容经过可执行测试、真实模型运行和独立AI审查；下文区分候选人参与与AI实际执行，不将AI操作或运行耗时计为个人编码或个人工时。

## 分工

| 工作 | 候选人参与 | AI辅助范围 |
| --- | --- | --- |
| 需求与范围 | 选择企业知识问答，限定三个主题、12份合成资料 | 梳理验收点、起草需求与规格 |
| 技术设计 | 选择单Agent、DeepSeek、本地embedding、混合检索及HTTP；讨论取舍 | 调研资料、设计接口与模块 |
| 会话与记忆 | 选择SQLite、结构化锚点加近期原始历史；讨论预算与失效策略 | 实现持久化、历史选择、记忆校验与降级 |
| 合成资料 | 阅读完整条文并确认接受 | 起草JSON、资料说明、变体及校验 |
| 业务实现 | 理解架构与Agent loop，确认关键行为边界 | 编写及修改业务代码、模型适配和工具 |
| 测试与验收 | 要求完整验收、提出资料变化后的连续追问验证 | 编写和运行测试、真实请求、检索/HTTP验证与引用核查 |
| 资料变更实验 | 同意由独立AI代理代办 | 独立代理先提出MOV→WEBM及预期，再执行和核查；后续另作回归重放 |
| 文档 | 提供个人投入和学习经历，参与修复决策 | 起草与整理文档，保留执行归属和证据 |

独立审查代理属于开发协作；交付运行时仍为单Agent。候选人没有声称亲自编写全部代码、运行全部测试或逐条审阅全部真实结果。

## 个人设计决策

- 将查询改写与混合检索列为核心能力；使用一个生成模型和一个本地向量模型，暂不增加Reranker。
- 采用服务端会话编号和SQLite，支持续问与重启，避免调用方反复传入完整历史。
- 比较全量历史、窗口和锚点方案后，选择三字段锚点与近期完整问答；与结束动作同次生成，不新增记忆请求。
- 以运行当天判断当前规则，不把固定演示日期当成所有任务的“今天”；不设置独立问题字符上限。
- 选择300秒任务总超时，并确认一次工具恢复、一次格式修正及第6工具后立即停止的边界。

## 锚点问题中的理解与验证参与

验收发现有效锚点保存了“15天与30天规定冲突”。候选人进一步讨论了“记住报销提交期限这个关注事项”和“保存已读企业结论”的区别，明确企业事实仍需每轮重新查证，也需要处理旧数据库中的污染锚点。

候选人要求修复保持原有记忆边界，增加合法问题与非法结论的正反例，保留原失败，并验证“冲突问答→隔离修改资料→显式重载→同会话追问”。AI完成实现、测试及真实回归；出现HTTP402后，候选人处理验证恢复条件，AI再继续运行。

124项测试、40轮最终真实回归、65处引用核对和独立审查均由AI执行。候选人的贡献是架构理解、设计取舍、修复约束和验证要求；具体收获见[复盘](05-retrospective.md)。
